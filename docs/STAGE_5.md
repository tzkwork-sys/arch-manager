# Stage 5 — обновления

## Статус

**Завершён. 25.09.2026 выполнена крупная ревизия GUI и update-session.**

## Проверка обновлений

Read-only backend получает детальный список из двух источников:

- официальные репозитории Arch через `checkupdates --nocolor`;
- AUR через `yay -Qu --aur`.

В GUI больше нет трёх отдельных карточек «Всего / Официальные / AUR». Сразу под заголовком показывается единый индикатор состояния:

- зелёная галка — обновлений нет;
- жёлтый `!` — найдено от 1 до 6 обновлений или проверка неполная;
- красный `!` — найдено 7 и более обновлений.

Ниже сразу находится таблица пакетов. В ней видны имя, установленная версия, новая версия и источник.

## Официальные пакеты и выбор AUR

Официальные пакеты по-прежнему обновляются только полным системным обновлением. Частично обновлять официальный набор Arch Manager не предлагает, чтобы не создавать неподдерживаемое частичное состояние Arch Linux.

AUR-пакеты теперь выбираются отдельно прямо в таблице. Для строк AUR есть checkbox; по умолчанию выбраны все найденные AUR-обновления. Пользователь может снять отметки и обновить только нужные AUR-пакеты.

Парсер по-прежнему удаляет ANSI terminal escape-последовательности из вывода AUR до разбора версий.

Фильтр «Все источники / Официальные / AUR» сохранён. Кнопка `ⓘ` строки открывает локальное описание установленного пакета через `pacman -Qi` без сети и административных прав.

## Защита перед обновлением

Настройка «создавать важную точку восстановления перед обновлением» сохранена, но отдельная постоянная строка «Защита включена» удалена из интерфейса.

Если защита включена, Arch Manager создаёт важную защитную точку внутри того же update-session до запуска `pacman`. Используется установленный root-owned helper `manage-restore-points`; при ошибке защитной точки установка не начинается.

## Один запрос пароля и реальный терминал

Обновление выполняется в отдельном реальном терминальном окне. Это намеренное решение: `pacman` и `yay` являются интерактивными программами и корректнее всего работают в настоящем TTY, где нормально отображаются ANSI-последовательности, шрифты, прогресс и вопросы `[Y/n]` / `[y/N]`.

`UpdatesPage` запускает только фиксированный `scripts/run-system-update-terminal.sh` через асинхронный `QProcess` из `src/gui/update_session.py`. В KDE launcher открывает отдельный Konsole; для других окружений предусмотрены безопасные fallback-терминалы. Сам GUI не строит shell-команды.

Пароль больше не запрашивается отдельным диалогом Arch Manager. В начале терминального сеанса runner выполняет свежий `sudo -k`, затем обычный `sudo -v`; пароль вводится один раз непосредственно в терминале и никогда не попадает в процесс GUI. До конца операции sudo-ticket поддерживается активным. Последующие привилегированные вызовы используют `sudo -n`, поэтому второго неожиданного запроса пароля не возникает.

Все вопросы `pacman`/`yay` пользователь видит и подтверждает прямо в терминале обычным способом. Встроенный псевдотерминал и строка ручной пересылки `y/n` удалены. После завершения runner оставляет итог на экране и ждёт Enter перед закрытием окна; затем GUI читает status-файл, обновляет состояние страницы и повторно проверяет список пакетов.

Порядок остаётся строгим:

1. при необходимости создаётся важная точка восстановления;
2. выполняется полное официальное обновление Arch;
3. только после успеха официального этапа устанавливаются выбранные пользователем AUR-пакеты.

`yay` никогда не запускается от root. Для внутренних sudo-вызовов AUR runner использует только уже выданный ticket и запрещает повторный интерактивный запрос пароля.

## Последний сеанс и журнал

Постоянная крупная карточка «Последний сеанс обновления» удалена. Вместо неё рядом со статусом есть компактная кнопка `ⓘ`.

Она открывает отдельное прокручиваемое окно с:

- результатом последнего сеанса;
- временем;
- количеством официальных и выбранных AUR-пакетов;
- ID защитной точки;
- результатом проверки необходимости перезагрузки;
- техническими деталями runner и списком пакетов.

История по-прежнему сохраняется в `$XDG_DATA_HOME/arch-manager/activity.jsonl` и отображается в разделе «Журнал».

## Граница безопасности

- проверка списка обновлений остаётся полностью read-only;
- GUI не собирает shell-команды и не использует `shell=True` / `bash -c`;
- update-session запускает только фиксированный project-owned terminal launcher и фиксированный runner;
- AUR package names проходят валидацию и передаются отдельными argv-аргументами;
- runner не использует `eval` и не применяет `--noconfirm`;
- официальный этап всегда выполняется раньше AUR;
- после ошибки официального этапа AUR не запускается;
- пароль администратора вводится напрямую в терминале, не сохраняется и не проходит через GUI.

### GUI и единая авторизация (ревизия 25.09.2026)

- Кнопки «Установить обновления» и «Проверить обновления» расположены справа на одной линии с заголовком «Обновления». Обе используют нативное оформление KDE, поэтому активное и неактивное состояние визуально однозначно.
- Единый статус страницы расположен компактной полосой непосредственно под заголовком: слева семантический значок/спиннер, рядом текст состояния, справа `ⓘ` последнего сеанса.
- Обновление открывается в отдельном реальном терминале. Пароль вводится один раз через `sudo -v` прямо там, а вопросы пакетных менеджеров обрабатываются нативно без промежуточной строки ввода в GUI.
