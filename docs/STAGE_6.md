# Stage 6 — обслуживание системы

## Статус

**Завершён в версии `0.6.1-stage6`.**

Stage 6 превращает прежний read-only экран «Обслуживание» в самостоятельный центр безопасной очистки. Сначала выполняется анализ, затем пользователь видит категории, объём и последствия, отмечает нужные пункты и только после отдельного подтверждения запускает очистку.

## Что анализируется

### Кэш обновлений

Arch Manager использует dry-run `paccache` и показывает объём, который будет освобождён именно при выбранной политике хранения. В карточке можно оставить 3, 2, 1 или 0 последних версий каждого пакета. Значение 3 остаётся рекомендуемым и используется по умолчанию; 0 версий означает полную очистку кэша загруженных пакетов. Установленные пакеты при этом не удаляются, но локальные копии для быстрого отката исчезают.

### Ненужные зависимости

Показываются пакеты, установленные как зависимости и больше не требуемые другими установленными пакетами. В GUI видны количество, имена и приблизительный установленный размер. Эта категория не выбирается автоматически.

### Системный журнал

Показывается текущий общий размер журналов. Очистка удаляет только архивные журналы старше 30 дней. Общий размер не включается целиком в обещанный объём освобождения, потому что активные журналы остаются на месте.

### Кэш миниатюр

Новая по сравнению с консольной версией категория. Очищается пользовательский `~/.cache/thumbnails`; миниатюры безопасно создаются заново по мере использования.

### Корзина

Новая категория. Показываются суммарный объём и количество объектов в корзинах текущего пользователя. Учитывается не только домашняя `~/.local/share/Trash`, но и freedesktop-корзины на других подключённых дисках (`.Trash/<uid>` и `.Trash-<uid>`), что важно для отдельных разделов вроде `/data` и внешних накопителей. Корзина никогда не отмечается по умолчанию, потому что после очистки восстановить эти файлы через корзину уже нельзя.

### Файлы настроек после обновлений

`.pacnew`, `.pacsave` и `.pacorig` по-прежнему не удаляются автоматически. Arch Manager показывает количество и несколько путей, а затем может открыть отдельный интерактивный сеанс `pacdiff -s` в Konsole. Решение по каждому файлу принимает пользователь.

## Интерфейс

Экран содержит:

- сводку «без учёта журналов можно освободить примерно …», чтобы общий размер journal не выглядел как гарантированно освобождаемый;
- отдельную карточку для каждой категории;
- безопасные категории, отмеченные по умолчанию;
- осторожные категории, которые пользователь выбирает сам;
- настраиваемое хранение 3/2/1/0 версий кэша пакетов с сохранением выбора в QSettings;
- итог выбранного объёма перед запуском;
- отдельное подтверждение очистки;
- закреплённую нижнюю панель действия «Очистить выбранное», которая остаётся доступной при прокрутке;
- повторный анализ после каждой операции;
- понятные сообщения об отмене Polkit, ошибке helper и частичной системной ошибке.

Успешная очистка, отмена и ошибка записываются в общий локальный «Журнал» Arch Manager. В записи сохраняются выбранные категории, поэтому обслуживание использует ту же историю действий, которая появилась на Stage 5 для обновлений.

## Граница безопасности

GUI всегда работает от обычного пользователя.

Системные действия Stage 6 выполняются только через новый root-owned helper:

`/usr/local/libexec/arch-manager/manage-maintenance`

и отдельное действие Polkit:

`org.archmanager.manage-maintenance`

Helper принимает только конечный набор действий:

- `package-cache`;
- `orphans`;
- `journal`.

Он не принимает пути, имена пакетов, произвольные команды или shell-фрагменты от GUI. Список orphan-пакетов пересчитывается самим helper непосредственно перед удалением. `eval`, `bash -c` и произвольное выполнение команд не используются.

Пользовательские категории (`thumbnails`, `trash`) обрабатываются без root и только по фиксированным каталогам текущего пользователя. Корневой каталог очистки не может быть символической ссылкой.

## Установка системного компонента

После применения Stage 6:

```bash
./scripts/install-stage6-helper.sh
```

Скрипт устанавливает helper, Polkit policy и ограничивающее правило Polkit. Для удаления только этой интеграции предусмотрен:

```bash
./scripts/uninstall-stage6-helper.sh
```

## Что намеренно не добавлено

Stage 6 не делает массовую очистку `~/.cache`, `/tmp`, браузерных профилей, Docker/Flatpak-данных или AUR build-кэша. Эти каталоги могут содержать рабочие данные, локальные изменения или иметь собственные правила очистки. Общая кнопка «удалить всё найденное» для них была бы слишком агрессивной.
