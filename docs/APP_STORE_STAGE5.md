# Arch Manager — App Store Stage 5

Дата реализации: 1 октября 2026.

## Реализовано

- В магазине появились отдельные пользовательские представления **«Установленные»** и **«Обновления»** поверх AppStream-каталога; технические пакеты из полного `pacman -Q` туда не добавляются.
- Карточки установленных приложений показывают установленную версию; при наличии обновления карточка показывает переход `текущая → новая`.
- Обновления desktop-приложений сопоставляются с официальными package updates, включая несколько AppStream components на один пакет и component с несколькими связанными package names.
- При выборе нескольких пакетов для одного AppStream component каталог предпочитает реально установленный пакет, а не первый попавшийся вариант из metadata.
- Введён общий `UpdateStateService`: Overview, страница «Обновления» и магазин используют один опубликованный результат проверки. Одновременные проверки объединяются и не создают конкурирующие состояния.
- Магазин больше не обязан самостоятельно запускать отдельный `pacman -Qu` в обычном production-flow: package-state слой получает update availability из общего состояния. Старый read-only путь сохранён только как изолируемый fallback для custom/test providers.
- Представление **«Обновления»** не содержит собственного updater. Кнопка **«Перейти к обновлениям»** открывает существующую страницу полного системного обновления Arch Manager. Partial-upgrade path для одного приложения не создавался.
- После установки/удаления приложение перечитывается без cache, общий update state инвалидируется, а страницы «Обновления» и Overview запускают синхронизацию без перезапуска Arch Manager.
- После успешного полного системного обновления магазин перечитывает состояние и версии без cache; Overview получает актуальный счётчик из общего update state.
- Установка/удаление через магазин записываются в компактный локальный activity log с временем, приложением, пакетом и результатом. В магазине показывается последняя операция.

## Restore point policy этапа 5

Отдельная точка восстановления **не создаётся для каждой одиночной установки или удаления приложения**. Это намеренное решение: такие операции уже выполняются через безопасный `pacman`-helper, а snapshot на каждое мелкое действие быстро засорял бы список точек восстановления.

Для **полного системного обновления** остаётся действовать существующая политика Arch Manager: при включённой настройке перед update-session создаётся защитная важная точка восстановления. То есть магазин не ослабляет защиту системного обновления и не создаёт десятки лишних snapshots.

## Проверки этапа 5

Добавлены regression/unit tests на:

- install → появление в «Установленных»;
- remove → исчезновение из «Установленных»;
- mapping package update → application;
- несколько AppStream components на один package;
- один AppStream component с несколькими package metadata;
- предпочтение реально установленного пакета;
- общий update state и объединение параллельных проверок;
- общий summary для Overview;
- отсутствие partial-update executor в магазине;
- переход к существующей странице «Обновления»;
- связи синхронизации после package/system update.

Финальный прогон в артефакте этапа 5: **349 passed, 8 skipped**. Пропуски относятся к Qt GUI-тестам в среде без установленного PySide6; синтаксис GUI-модулей проверен отдельно через `compileall`/`py_compile`.
