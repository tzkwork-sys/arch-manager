# Arch Manager — App Store Stage 7.4.2: cleanup новых orphan-пакетов после удаления AUR

**Дата:** 01.10.2026  
**Статус:** исправление Stage 7.4/7.4.1.

## Проблема

`yay -Rns <target>` корректно удаляет целевой пакет и его обычные ненужные зависимости, но отдельный companion/split package может не входить в dependency-граф цели. На практике после удаления `tetris` пакет `tetris-debug` стал новым orphan и появился в разделе обслуживания как «Ненужная зависимость».

Это не означает, что основной пакет остался установлен: `tetris-debug` — отдельная запись pacman. Старый workflow проверял исчезновение только целевого package name и потому не контролировал orphan-дельту, созданную самой remove-транзакцией.

## Новый контракт удаления

1. Непосредственно перед удалением terminal runner сохраняет исходный список `pacman -Qtdq`.
2. Основной пакет по-прежнему удаляется интерактивно через `yay -Rns -- <target>`.
3. После подтверждённого удаления Arch Manager снова запрашивает `pacman -Qtdq`.
4. Вычисляется только разница `orphans_after - orphans_before`.
5. Если появились новые orphan-пакеты, они показываются пользователю отдельным списком и удаляются второй интерактивной транзакцией `yay -Rns -- <new-orphans...>` только после подтверждения.
6. Проверка повторяется ограниченное число раз, чтобы cleanup не оставлял следующий слой зависимостей.
7. Orphan-пакеты, которые существовали до удаления приложения, автоматически не затрагиваются.
8. Если основной пакет удалён, но post-remove cleanup отменён или завершился ошибкой, GUI показывает частичный результат, а не ложный полный успех.

## Safety

- Нет глобального `pacman -Qtdq | xargs ...` cleanup после каждого удаления.
- Нет `--noconfirm`.
- Все имена новых orphan-пакетов повторно проходят строгую проверку package-name перед передачей в `yay`.
- Pre-existing orphan packages защищены baseline snapshot и не попадают в автоматический cleanup этого приложения.
- Пользовательские данные в `$HOME`, конфиги самого пользователя и build cache `yay` не являются package ownership и автоматически не удаляются.

## Что это исправляет

Типовой случай `tetris -> tetris-debug` теперь выглядит так:

- пользователь подтверждает удаление `tetris`;
- после удаления Arch Manager видит, что `tetris-debug` стал новым orphan;
- терминал показывает `tetris-debug` отдельно и просит подтверждение;
- после подтверждения он удаляется;
- раздел «Обслуживание» не должен получать orphan, созданный именно этой AUR-remove операцией.

При этом старые unrelated orphan-пакеты остаются в разделе обслуживания и не смешиваются с удалением конкретного приложения.
