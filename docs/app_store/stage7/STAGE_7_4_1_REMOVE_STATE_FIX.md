# Arch Manager — App Store Stage 7.4.1: синхронизация состояния после удаления AUR

**Дата:** 01.10.2026  
**Статус:** исправление Stage 7.4.

## Исправлено

1. `AurService.refresh_local_state()` теперь считает `pacman -Qm` единственным источником истины для локального AUR-состояния. Если удалённый пакет больше не найден среди foreign-пакетов, его прежний `installed=True` принудительно сбрасывается. Это работает и когда `pacman -Qm` пуст, и когда в системе остались другие AUR/foreign-пакеты.
2. Кнопка `Обновить каталог` в представлении `Установленные` теперь повторно запрашивает `AurService.installed_async()`, а не только запускает AUR-поиск каталога.
3. Если planner обнаруживает устаревшую карточку (`package not installed` или пакет больше не foreign/AUR), диалог автоматически перечитывает локальное состояние вместо требования ручного обновления.
4. В интерфейсе и terminal runner уточнена область действия `yay -Rns`: пакетные файлы и более не нужные зависимости удаляются пакетным менеджером; пользовательские данные в `$HOME` и build/cache yay намеренно не удаляются автоматически.

## Причина дефекта

Stage 7.4 передавал в `refresh_local_state()` объект карточки, который уже содержал `installed=True`. Декоратор локального состояния оставлял объект неизменным, если точного совпадения в `pacman -Qm` не было. После успешного удаления это сохраняло устаревший флаг установки. Одновременно общий reload страницы не обновлял AUR installed snapshot.

## Контракт удаления

Удаление остаётся интерактивным и выполняется строго через:

```text
yay -Rns -- <package>
```

После возврата `yay` terminal runner проверяет, что `pacman -Qq -- <package>` больше не находит пакет. Автоматическое удаление пользовательских профилей/настроек и AUR build cache не выполняется, поскольку эти данные не являются безопасной частью package transaction.
