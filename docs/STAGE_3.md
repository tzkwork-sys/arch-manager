# Этап 3 — точки восстановления: просмотр

Версия: **0.3.1-stage3**.

## Что реализовано

Раздел **«Точки восстановления»** показывает сохранённые состояния системы без действий над ними.

После последующего развития проекта список встроен в единую страницу **«Восстановление»**. В текущем интерфейсе доступны:

- название, дата и причина создания;
- отметка важности;
- меню `⋯` для действий и технических сведений;
- стандартный множественный выбор строк через `Ctrl`/`Shift`;
- пакетное удаление выбранных точек после одного общего подтверждения.

Поиск, отдельные счётчики и колонка размера сейчас намеренно не показываются, чтобы экран оставался компактным.

Важные точки выделяются меткой `★ Важная` и более заметным начертанием. Обычные и автоматические точки остаются нейтральными.

## Состояния экрана

Таблица и фильтры показываются только когда список действительно прочитан.

Если список недоступен, вместо пустой таблицы отображается отдельная карточка состояния с понятным объяснением и действиями **«Настроить доступ»** / **«Повторить»**. Если точек пока нет, также показывается отдельное пустое состояние.

## Безопасный доступ на чтение

Некоторые установки Snapper не позволяют обычному пользователю читать конфигурацию `root`. Arch Manager не расширяет `ALLOW_USERS`, потому что это дало бы пользователю не только чтение, но и возможность выполнять операции Snapper.

Вместо этого кнопка **«Настроить доступ»** выполняет одноразовую установку узкого root-owned helper:

- helper умеет только вывести список точек через `snapper list`;
- создание, удаление, изменение и восстановление в helper отсутствуют;
- для текущего локального пользователя создаётся отдельное правило `sudoers`, разрешающее без пароля запускать только этот helper;
- само добавление правила один раз подтверждается через системный Polkit-диалог;
- последующие открытия списка не запрашивают пароль.

Таким образом, этап 3 остаётся пользовательски **только для просмотра**, а повышенные права ограничены одной заранее определённой операцией чтения.

## Быстрая загрузка списка

Текущий GUI не вычисляет эксклюзивный размер каждого snapshot. Именно серия `btrfs filesystem du` была основной причиной минутной загрузки на реальной системе. Read-only helper получает только metadata Snapper с `--disable-used-space`.

Для повторных открытий используется локальный cache `~/.cache/arch-manager/restore-points.json`. Перед использованием cache root-owned read helper вычисляет дешёвый fingerprint конфигурации Snapper и metadata `/.snapshots/*/info.xml`. Если fingerprint совпадает, повторный полный список Snapper не запрашивается; после создания, удаления, переименования или изменения важности fingerprint меняется и список перечитывается.

## Что этап 3 не делает

Экран просмотра не содержит функций:

- создания точки;
- удаления;
- переименования;
- изменения важности;
- восстановления системы;
- изменения политики хранения.

Эти действия относятся к следующему этапу.
