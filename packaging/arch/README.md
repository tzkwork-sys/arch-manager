# Arch Manager: пакет Arch Linux

Предварительная версия **0.7.0-beta.1**, версия pacman **0.7.0beta1-1**.
Пакет `arch-manager` содержит Python/Qt-приложение; `any` означает отсутствие
скомпилированного машинного кода, а не поддержку других дистрибутивов.
Основное проверяемое окружение — Arch Linux x86_64 / KDE Plasma.

## Установка готового пакета

Скачайте `arch-manager-0.7.0beta1-1-any.pkg.tar.zst` и `SHA256SUMS.txt` со
[страницы выпуска](https://github.com/tzkwork-sys/arch-manager/releases/tag/v0.7.0-beta.1).
В папке загрузки:

```bash
sha256sum --check --ignore-missing SHA256SUMS.txt
sudo pacman -Syu
sudo pacman -U ./arch-manager-0.7.0beta1-1-any.pkg.tar.zst
arch-manager-gui --check
```

После установки откройте **Arch Manager** в меню приложений. GUI запускается
обычным пользователем, не через sudo. Зависимости устанавливает pacman;
`xterm` обеспечивает запасной терминал для интерактивных обновлений.
Нужны действующая графическая сессия, запущенный агент Polkit и возможность
подтвердить действия паролем администратора. В KDE это обычно
`polkit-kde-agent`; в других окружениях агент нужно настроить самостоятельно.
`--check` проверяет файлы, основные зависимости и права helpers, но не доказывает,
что графический агент работает или что восстановление безопасно.

## Что включено

- Интерфейс, ярлык, иконка и терминальные сценарии официальных/AUR-обновлений.
- Root-owned helpers установки/удаления приложений, обслуживания, управления
  Snapper и SMART-диагностики в `/usr/lib/arch-manager`.
- Политики Polkit только для фиксированных helpers: локальная активная сессия,
  пароль администратора для каждого действия, без привязки к имени автора.
- Нет запуска установщиков в `post_install`, изменения загрузчика, создания ISO,
  snapshots или общих беспарольных правил sudo при установке пакета.

Дополнительно установите `yay` для AUR, `smartmontools`/`nvme-cli` для диагностики,
`snapper`/`btrfs-progs` для snapshots. Пакет **не создаёт конфигурацию Snapper**.
Для уже настроенного Snapper можно явно разрешить чтение его метаданных
текущему пользователю:

```bash
arch-manager-enable-snapper-read "$(id -u)"
```

Это отдельный запрос администратора и узкое правило sudo только для
`/usr/lib/arch-manager/read-restore-points`. Оно не разрешает изменять snapshots.
Recovery helper, ISO и загрузочные файлы **не входят в этот пакет**. Возможность
Recovery в интерфейсе не означает, что она включена или проверена.

## Переход с установки из исходников

Закройте приложение и завершите системные операции. Удалите старые системные
компоненты соответствующими `uninstall-*-helper.sh` из прежней установленной
копии, руководствуясь `docs/INSTALL.md`. Сохраните snapshots и резервные копии.
Старые пользовательские ярлык и launcher имеют приоритет над системными:
после проверки их происхождения удалите
`~/.local/bin/arch-manager-gui`,
`~/.local/share/applications/arch-manager-gui.desktop` и старый ярлык рабочего
стола. Не запускайте старые установщики поверх пакетной установки.
Если pacman сообщает конфликт файлов, разберитесь с прежней установкой;
**не используйте `--overwrite '*'`**.
В частности, `setup-restore-points-read-access.sh` прежней версии мог создать
`/usr/lib/arch-manager/read-restore-points` вне pacman. Проверьте его владельца
командой `pacman -Qo /usr/lib/arch-manager/read-restore-points`; если файл не
принадлежит пакету и точно установлен прежним Arch Manager, сохраните его
отдельную копию и уберите конфликтующий файл до установки пакета. Старые
правила чтения Snapper тоже следует проверить; новый пакет их не удаляет.

## Сборка и проверка

Распакуйте `arch-manager-0.7.0beta1-1-build.tar.gz`. В его папке от обычного
пользователя:

```bash
sudo pacman -Syu --needed base-devel
makepkg --syncdeps
```

Либо используйте файлы из `packaging/arch/` репозитория. Проверяются SHA-256
исходников и каждого файла рецепта. `check()` запускает upstream-тесты и
изолированную проверку Qt; `package()` проверяет раскладку и безопасные self-tests.
Для повторной чистой сборки используйте `makepkg --cleanbuild --force`.
Рекомендуется также сборка в чистом chroot через `devtools` и испытание
установки/обновления/удаления в отдельной Arch VM.

## Обновление и удаление

Обновляйте через `pacman -U` новым файлом пакета после полного обновления Arch.
Все пакетные файлы учитываются pacman; пользовательские настройки сохраняются.
Если включали чтение Snapper, перед удалением явно уберите созданное правило:

```bash
sudo rm -- "/etc/sudoers.d/arch-manager-read-restore-points-$(id -u)"
sudo pacman -R arch-manager
```

Команду удаления правила выполняйте только если включали доступ и файл
действительно относится к Arch Manager. Snapshots, пользовательские журналы,
старые Recovery ISO и загрузочные записи пакет не удаляет.

## Публикация в AUR

Название `arch-manager`; аккаунт AUR и зарегистрированный SSH-ключ обязательны.
После проверки рецепта и правил AUR скопируйте в отдельный AUR-репозиторий
`PKGBUILD`, `.SRCINFO` и все локальные файлы из массива `source`.
Не добавляйте бинарный пакет, распакованные исходники и каталоги `src`/`pkg`.
При изменении файлов обновляйте SHA-256 в `PKGBUILD`, затем
`makepkg --printsrcinfo > .SRCINFO`. Публикация бинарного пакета на GitHub
сама по себе **не публикует его в AUR**.

## Статус испытаний

Это beta. Сборка и автоматические проверки не заменяют установку на чистой
Arch-системе. Реальные пакетные операции, отмена авторизации, обновление и
удаление на отдельной VM пока не подтверждены. Recovery не входит в пакет
и не получает никаких дополнительных гарантий. Лицензия: GPL-3.0-only.
