# Arch Manager v1.8.4

## Локальное восстановление без USB

Arch Manager умеет восстановить корневой Btrfs-подтом `@` без флешки: работающая система подготавливает одноразовую запись systemd-boot и перезагружается в автономную Recovery-среду. Само восстановление выполняется уже вне рабочего `@`.

## Что исправлено в v1.8.4

- Восстановленный `@` монтируется отдельно как настоящий root mount и только после этого используется `arch-chroot` + `mkinitcpio -P`. Это устраняет предупреждение `root is not a mountpoint` и ошибку `failed to detect root filesystem`, замеченные в реальном тесте.
- Описания Snapper из `info.xml` корректно декодируются из XML numeric entities, поэтому кириллица больше не отображается как `&#x420;...`.
- Recovery пишет маркер последнего восстановления в отдельный `@snapshots`.
- В Arch Manager добавлен пункт **«Последнее восстановление / старый @.broken»**. Он проверяет текущий `@`, failed units systemd, наличие резервного старого корня и вложенных подтомов. Удаление предлагается только после прохождения проверок и отдельного подтверждения пользователя.
- Для восстановления, уже выполненного версиями 1.8.0–1.8.3, новый пункт умеет использовать существующий `restore-*.txt`.
- Старый `@.broken-*` не удаляется автоматически.
- Сохраняются исправления v1.8.3: executable permissions Recovery в ArchISO и автозапуск через Bash/systemd getty.

## Безопасность

Аварийная USB-флешка остаётся резервным вариантом. Локальное восстановление использует тот же `arch-recovery.sh`, что и флешка. Перед изменением корня текущий `@` сохраняется как `@.broken-YYYYMMDD-HHMMSS`, а отдельный `/boot` резервируется до пересборки UKI/initramfs.
